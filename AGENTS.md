# AGENTS

## Purpose

These instructions help AI coding agents make safe, CI-compatible changes in this repository.

## Start Here

- Project overview and local setup: [README.md](README.md)
- PR validation workflow: [.github/workflows/pr.yml](.github/workflows/pr.yml)
- CI/CD deployment workflow: [.github/workflows/ci.yml](.github/workflows/ci.yml)

## Required Commands

- Install deps: `yarn install`
- Dev server: `yarn dev`
- Lint: `yarn lint`
- Test (with coverage): `yarn test`
- Build/export static site: `yarn build`

Run `yarn lint` and `yarn test` after code changes. Run `yarn build` for routing/static-export changes.

## Repository Map

- Routing uses the Next.js pages router under [pages](pages) with `*.page.tsx` naming.
- Reusable UI components live in [components](components).
- Shared utilities/types/helpers live in [lib](lib).
- Client-side classes/utilities also exist in [modules](modules).
- Markdown post content is in [posts](posts).

## Conventions To Follow

- TypeScript is strict; keep types explicit and avoid `any` unless already established.
- Use path alias imports with `@/*` where appropriate (see [tsconfig.json](tsconfig.json)).
- Follow ESLint rules in [eslint.config.mjs](eslint.config.mjs), including Prettier formatting.
- Preserve existing file naming style (for example `index.page.tsx`, `about.page.tsx`).

## Testing Notes

- Jest is configured through [jest.config.js](jest.config.js) with `jest-environment-jsdom`.
- Existing tests are colocated under page-specific test folders such as [pages/**tests**](pages/__tests__) and [pages/posts/**tests**](pages/posts/__tests__).
- Keep new tests consistent with React Testing Library usage in existing tests.

## CI Compatibility

- GitHub Actions uses Node 20 and Yarn with `--frozen-lockfile`.
- PR checks run lint, tests, and build; do not merge changes that fail any of these steps.
- Static export adjustments are performed in CI (moving `out/404/index.html` to `out/404.html` and creating `out/.nojekyll`). Avoid manual edits to generated output.

## Avoid Editing Generated/Build Artifacts

Do not manually edit paths typically generated by tooling unless the task explicitly requires it:

- `.next/`
- `out/`
- `coverage/`
- `next-env.d.ts`
